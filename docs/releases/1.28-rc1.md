# What's On My Food 1.28-rc1

Study/test release candidate prepared September 19, 2026. Unlimited AI access remains enabled as requested. Signed artifacts are built; device acceptance testing is still pending. This candidate has not been uploaded or published.

## Release notes to share with testers

This update adds automatic food-recall checks for scanned products and pantry items, saved check status, and optional recall notifications. Product details open expanded, certification artwork is clearer, and generic dietary claims are marked “Not verified.” Spanish and French badge labels are included. Unlimited Bitwise AI access remains enabled for study participants. Always compare recall notices with the package and lot details; no match is not a safety guarantee.

## Changes since 1.19-rc-2

- Check scanned products for recalls as soon as their details load, without requiring the product to be saved first.
- Check pantry items when their identity changes and schedule daily background checks. Cache successful checks, retain previous results on errors, and avoid duplicate recall alerts. Android may delay background work; notification permission is required for system alerts.
- Use official certification artwork where supported by source data; distinguish generic dietary claims with labeled icons and “Not verified.”
- Open product-detail sections expanded by default.
- Include the matching backend's barcode recall queries, bounded pagination, and incomplete-response handling. Its deployed revision still needs confirmation.
- Fix four missing dietary-label translations in both Spanish and French, removing the blocking translation lint errors.
- Set compile/target SDK to 36, retaining minimum SDK 26. Temporarily opt out of predictive-back callbacks to preserve the existing in-app WebView history behavior.

The SDK update addresses the [current Google Play target requirement](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en). The temporary back-navigation setting follows the [Android 16 migration guidance](https://developer.android.com/about/versions/16/behavior-changes-16). It does not replace on-device navigation, edge-to-edge, or tablet testing.

JDK 25's JAR verifier reports self-signed certificate, missing timestamp, and ZIP/JarInputStream ordering warnings for the AAB. Bundletool validation passed; these checks are not a claim of Play Console acceptance.

The native review checked ELF layouts, not only ZIP packaging. Six libraries initially triggered a simplified RELRO-end check, but each RELRO covers an entire writable LOAD segment and its rounded protection range overlaps no other writable data. The [Android linker handles this whole-segment layout separately](https://android.googlesource.com/platform/bionic/+/android16-qpr2-release/linker/linker_phdr_16kib_compat.cpp); the initial warning is not a confirmed compatibility failure. No dependency upgrade was made on that basis. Actual 16 KB camera, language-detection, and translation checks remain pending.

## Before distributing to participants

- Complete the [plain-language device smoke test](../testing/1.28-rc1-smoke-test.md), especially update/data preservation, scanning, recall failures, notification delivery, and Android 16 navigation. No device was connected during this preparation.
- Confirm the hosted service contains the matching `backend/retailer/src/foodRecallProxy.js` changes. Hosted readiness confirms configuration/availability, not the deployed code revision or successful live FDA matches. No backend deployment was performed.
- Run the 16 KB runtime checks before claiming tested support on those devices. Static native alignment/layout checks passed, but no 16 KB device or emulator was exercised.
- Use a study/testing track, not a public paid release. Hosted Play billing is not configured, and subscription purchases were not tested.
- Existing [M8-02 study sign-off blockers](../testing/m8-02-controlled-study-modes.md#remaining-blockers-and-closure-checks) are not closed by this release: frozen inputs, mode administration, paired device execution, and attribution/input-parity checks need their own evidence.

Existing backend hardening concerns remain: alternative/availability routes are rate-limited but do not check the app token, and readiness can accept a built-in default token. These were not introduced or fixed by this release. Retailer credentials stay server-side, but readiness must not be described as a security audit.

Recall results are limited to the configured FDA source and available product data. A potential match requires checking package/lot information; no known match is not a food-safety guarantee. Controlled automated tests do not prove current live provider behavior, actual notification delivery, or elapsed daily scheduling.
