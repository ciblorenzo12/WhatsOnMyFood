# What's On My Food 1.0.0-beta1

## Release purpose

This is the first Beta 1.0 build prepared for the Milestone 6 advisor demonstration and participant testing. It is a signed Android release candidate, not a public production release.

## Description

What's On My Food Beta 1.0 brings the complete food-scanning experience into a more stable, test-ready build. Users can scan a product barcode or capture an ingredient label, review a rule-based health result and detailed findings, read a plain-language Bitwise AI explanation, save products to their pantry, and compare alternatives. The app clearly identifies whether product information is online, cached, stale, recovered, or offline, and it keeps the product and deterministic findings usable when an external AI or retailer service is delayed or unavailable.

Since the first `0.31.0-rc1` candidate, this beta includes the following improvements:

- **More accurate online and offline behavior:** Product lookup now checks connectivity before deciding how to use cached data. Offline products are clearly labeled as offline copies instead of appearing fresh, while online refreshes preserve local pantry and analysis state.
- **Unlimited AI access for testing:** The normal three-per-day Bitwise limit is disabled in both debug and Beta release builds. Participants can complete every assigned AI-supported scan without a subscription prompt or usage counter interruption. The freemium policy remains in the code and can be re-enabled after testing.
- **Reliable first-scan Bitwise results:** The app now wakes the hosted Bitwise service during startup. A cold service receives up to two bounded automatic retries with a longer protected request window, reducing the case where the first scan failed but an immediate manual retry succeeded.
- **Safer failure handling:** Timeouts, rate limits, malformed responses, startup pages, and HTTP 502, 503, and 504 failures use understandable messages without exposing raw provider details. If Bitwise remains unavailable, the product rating and rule-based GOOD, WATCH, and INFO findings stay visible with a manual retry option.
- **Clearer participant access messaging:** Subscription and usage screens now explain the unlimited testing state, with matching English, Spanish, and French text.
- **Stronger regression coverage:** New tests cover release identity, participant AI access, online/cache/offline decisions, source-state presentation, first-scan cold-start recovery, and bounded retry behavior.
- **Demo and quality preparation:** The project now includes a complete Milestone 6 end-to-end matrix, backend failure evidence, critical-defect triage, reliable sample products and barcodes, release hashes, a concise walkthrough, and controlled fallback evidence.
- **Beta release identity:** The application is now version code 13 with the user-facing version name `1.0.0-beta1`, built as a signed APK for advisor and participant evaluation.

This beta is intended to demonstrate a stable baseline while keeping external-service limitations honest. Live product records, Bitwise explanations, maps, and retailer availability still depend on network access and configured services, but those dependencies no longer need to block the core product-review flow.

## Beta-specific behavior

The normal three-per-day Bitwise freemium restriction is disabled in this Beta so test participants can complete every assigned AI-supported scan. Billing startup and usage counting remain bypassed while `UNLIMITED_AI_TESTING=true`. The underlying freemium policy remains covered by tests and can be restored after participant testing.

The app now warms the hosted Bitwise service at startup and permits two bounded automatic cold-start retries. If the service still cannot respond, deterministic product findings remain visible and the Bitwise card offers a manual retry.

## Known beta limitations

- Live product, Gemini, map, and retailer results require network access and valid hosted-service configuration.
- Product-source records can change after this build; run the documented barcode preflight before the advisor session.
- Marketplace development samples must be identified as samples, not current store inventory.
- This beta was rehearsed on the SM-X800 tablet. Broader phone and API-26 coverage remains a later release activity.
